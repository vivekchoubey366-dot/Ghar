============================================================
DEPENDENCY RULES
============================================================

1. storage.js must load before authentication/session logic.

2. helpers.js and formatters.js must load before modules
   that use their functions.

3. validators.js and permissions.js must load before forms,
   authentication and protected UI actions.

4. Core/Foundation must load before UI.

5. UI must load before page-specific functionality.

6. api.js must load before all API modules.

7. auth-api.js must load before authentication modules.

8. Property API must load before property functionality.

9. Authentication/session modules must load before protected
   dashboard, seller and account functionality.

10. Property modules must load before property-specific pages.

11. Transaction modules must load before transaction pages.

12. Communication modules must load before messaging,
    enquiry and notification pages.

13. Admin modules must load after authentication and API layers.

14. app.js must ALWAYS be the final GHAR JavaScript file.


============================================================
PAGE RULE
============================================================

Every HTML page should load only the JavaScript required
for that page.

Do NOT load every GHAR JS file on every page unnecessarily.


============================================================
SECURITY RULE
============================================================

Frontend permissions are UI controls only.

The server MUST independently enforce:

- Authentication
- Authorization
- Role permissions
- Property ownership
- Property modification rights
- Property deletion rights
- Payment verification
- Document access
- User data access
- Admin permissions
- API access control

Never trust frontend permission checks as security.

============================================================
FINAL RULE
============================================================

One function = one responsible module.

Avoid:

- Duplicate functions
- Duplicate API calls
- Inline JavaScript
- Multiple competing routers
- Multiple authentication systems
- Page-specific copies of global utilities
- Circular dependencies
- Nested duplicate JS folders

GHAR should use one canonical JavaScript architecture.
